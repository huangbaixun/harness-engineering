# Evolve Harness from evidence

Find the active callers, actual behavior and original purpose of each proposed
removal. Distinguish obsolete policy from historical records and vendored upstream
resources. Do not delete licenses, source provenance or exact upstream companions.

For each change state the observed problem, affected workflow, proposed replacement,
validation and rollback. Model upgrades and a few successful tasks are reasons to
re-evaluate, not proof that security or failure handling is unnecessary. Compare
representative old/new behavior, including failures, and disclose limited samples.

Remove forced context-percentage termination in favor of explicit minimal checkpoints
and native compaction. Remove universal instruction/module/token quotas and fixed
model aliases when unsupported by project evidence. Keep justified project-specific
limits. Do not change host/user model selection implicitly.

Consolidate duplicate reviewer pipelines into the selected execution workflow.
Keep relevant verification and review; do not mandate every reviewer for every edit.
Delete empty default hook registrations. Deterministic checks belong at the control
point that actually enforces them, whether explicit CLI, pre-commit, CI or trusted
hooks. Check error propagation; registration alone guarantees nothing.

Preserve user scope, native permissions, requirements, data protection and
verification evidence. Narrow supplemental path guards cannot enforce shell
permissions. Keep opt-in external effects opt-in; improvements do not authorize
Issue writes, auto-commit, push, deployment or global changes.

Keep runtime state outside stable instructions. New checkpoint writes go through
scripts/harness_state.py to the configured neutral file; old progress is read-only.
Use host observability for actual token/cost metrics; unavailable measurements are
unknown. Optional local telemetry records event metadata only, never inferred cost.

For skill changes use the repository's paired behavioral evaluation workflow.
Run relevant regression checks, inspect results and document remaining gaps.
Measure outcomes (task correctness, failures, interventions, measured latency/cost),
not counts of hooks/rules or claims that a failure can never recur.
