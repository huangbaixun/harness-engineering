## 后端 提示卡

如果想不到，从这些场景想——

| 类型 | 典型失败 |
|------|--------|
| API 改动 | AI 顺手改了字段名 / 改了返回结构 / 多加了几个不必要的字段 |
| 数据库迁移 | AI 加了一个字段但没写 migration / 写了 migration 但 down 漏写 |
| 依赖引入 | AI 为一个小功能引入大型依赖（redis / kafka） |
| 错误处理 | AI 加了 try/catch 但 silent swallow / 错误没记录 |
| 日志规范 | AI 在 prod 路径加 console.log / 把敏感字段打了出来 |
| 性能 | AI 在循环里 await / N+1 query |

---

## 前端 提示卡

| 类型 | 典型失败 |
|------|--------|
| 组件样式 | AI 加 class 时改了已有组件的视觉 |
| 状态管理 | AI 在不该用 global state 的地方用了 / 反之 |
| 全局变量 | AI 改了 :root 的 CSS 变量，全 app 颜色都变 |
| 浏览器兼容 | AI 用了某个新 API 但没加 fallback |
| 路由 | AI 加路由时改了已有路由的 path |
| 构建 | AI 加了某个包但没考虑 SSR / tree-shake |

---

## QA 提示卡

| 类型 | 典型失败 |
|------|--------|
| 测试覆盖 | AI 改了实现但没加测试 |
| 边界用例 | AI 测试只 cover happy path，缺空值/异常 |
| 回归保护 | AI 改完，原来的测试挂了它没察觉 |
| mock 数据 | AI 测试用了硬编码 mock，与真实 schema 偏离 |
| 测试命名 | AI 测试名 it("works") 这种无信息名 |
| flaky | AI 写的测试依赖时序，CI 偶尔挂 |

---

## PM 提示卡

| 类型 | 典型失败 |
|------|--------|
| 需求边界 | AI "顺手"加了你没要求的功能 |
| 决策记录 | 上次为什么这么做没人记得 |
| 优先级声明 | AI 把 P2 任务做到 P0 工作量 |
| scope 漂移 | 初版讨论是 A，实现出来是 A + B + C |
| 沟通归档 | 重要的设计决定只在 chat 里，三个月后丢失 |
| 一致性 | 多个 PR 之间的术语 / 字段 / 样式不一致 |
